# 申万三级全行业投票（Subagent 规范）

## 目的

修正此前「按行业切片列举」导致的伪频次问题：**每个 subagent 必须对同一份申万三级（SW2021）主表中的每一行独立投票**，再由聚合脚本统计得票（或加权得票），用于 Top-N 赛道筛选。

## 主表文件

- 路径：`data/sw_l3_master.csv`
- 字段：
  - `idx`：0 起始行号，**与投票文件行序一一对应**（便于校验完整性）。
  - `行业代码`：如 `850111.SI`。
  - `行业名称`：申万三级名称。
  - `上级行业`：申万二级名称（供子代理理解语境，不参与计票键）。

主表由 `akshare.sw_index_third_info()` 导出快照生成；若申万官方调整分类，需重新导出主表并固定版本说明。

## 投票定义（每个 subagent 必须遵守）

1. **全集**：对主表中 **每一行**（当前为 **336** 行）给出投票，不得缺行、不得重复行、不得增删行业代码。
2. **票型（默认）**：`vote ∈ {0,1}`
   - `1`：在统一研究框架下（例如：康波/涛动 + 指定投资哲学 + 持有至目标日期），认为该三级行业在统计期内 **值得纳入正向清单**（可理解为「赞成票」或「入选池」）。
   - `0`：不纳入正向清单（否定/弃权均记 0；若需区分，可扩展为 `-1/0/1`，但聚合脚本须同步升级）。
3. **独立性**：不同 subagent 使用 **相同主表**、**相同 vote 语义**，仅允许在「框架解读权重」上不同（例如宏观派 vs 产业派），不得改表。

## Subagent 输出格式（机器可聚合）

每个 subagent 输出一个 CSV 文本块（或保存为 `research/votes/<agent_id>.csv`），要求：

- 表头固定：`idx,行业代码,行业名称,vote`
- 行数 **必须等于** 主表行数；`idx` 从 0 连续递增；`行业代码`、`行业名称` 与主表对应行 **完全一致**（便于 diff 校验）。
- `vote` 仅允许 `0` 或 `1`。

示例（前两行）：

```csv
idx,行业代码,行业名称,vote
0,850111.SI,种子,0
1,850112.SI,粮食种植,1
```

## 与人类/模型 subagent 的对接说明

- 在发起 Task 时，将 `data/sw_l3_master.csv` **全文作为附件或上下文**一并下发。
- 明确要求返回 **完整 CSV**，并自检行数是否等于主表行数。
- 若单次生成易截断，可采用「分段生成 + 本地拼接」或「按 idx 区间分多次生成后纵向合并」，**合并后仍须与主表逐行对齐校验**。

## 聚合

见 `research/aggregate_sw_l3_votes.py`：读取 `research/votes/*.csv`，按 `行业代码` 汇总 `vote_sum`，并输出按得票排序的 CSV。
